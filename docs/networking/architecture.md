# Decentralised world foundation

The playable Vite/WebGPU world and its normal game route remain intact. `network/` is an experimental Node proof of the future world protocol. The optional `?demo=network` browser mode sends player state through a local BroadcastChannel or a localhost WebSocket bridge to the two-node reference transport. Federation schemas and portal handoffs are currently Node protocol code; they are not yet wired to the cave's live gameplay transition. World code should eventually depend on `NetworkTransport`, not a provider API. A browser adapter would use the same application messages over WebRTC or a gateway.

Identifiers are distinct: `elsemesh-node:<SHA-256 of Ed25519 SPKI>`, `elsemesh:<player>`, `elsemesh:<world>`, `elsemesh:<sector>`, `sha256:<asset bytes>`, and an application session identifier. The node's private key is local and must remain outside Git. An IP address, Tailscale address, ZeroTier address, and libp2p Peer ID are routes or transport identities; none substitutes for the application NodeID. Two nodes may both advertise `192.0.2.10` from different sites and remain distinct by NodeID. Route selection must include site/transport scope rather than merging private-address strings globally.

`network/transport.mjs` defines lifecycle, discovery, connection, reliable and transient sends, service advertising, route and metrics calls. `TcpUdpTransport` demonstrates the contract with explicit trusted peer routes. It is a development reference only: its TCP/UDP application payloads are **not encrypted** and discovery/relay are not implemented. Do not expose it to public networks or use it for production gameplay. A production adapter must authenticate peers, encrypt traffic, bound resource use and report direct/relay state truthfully.

The reliable category includes inventory, quests, manifests, persistent world edits and authority changes. The transient category includes position, facing, animation and vehicle movement. Transient updates must be allowed to drop rather than stall newer states. This proof uses separate UDP datagrams. The optional browser demo rejects stale sequences and interpolates remote poses; full game state reconciliation and rollback are not implemented.

No distributed consensus is used for frame-by-frame movement. A sector has an explicit authority NodeID and epoch. A transfer is signed by the source authority and checked against trust, sector ownership, epoch, expiry and replay ID. Sector clocks, persistence, conflict resolution, migration of connected players and governance are future work.

AI World Forge output is only a proposal. A future acceptance flow must validate assets, hash them, sign a proposal, apply an authority/governance policy, then distribute an accepted manifest. A generated cave or terrain asset must never become authoritative merely because a model or peer emitted it.
